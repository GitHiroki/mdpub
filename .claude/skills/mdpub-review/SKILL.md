# mdpub レビューとマージ

推敲した書き手とは別のコンテキストでレビューし、基準を満たす PR だけをマージする。
レビューを分ける目的は、書き手の思考過程に引きずられないことにある。
そのため、このスキルの手順は「レビュアーに何を渡さないか」を中心に組んでいる。

## 層の分担

| 層 | 担当 | 対象 |
| --- | --- | --- |
| 機械チェック | `scripts/check_docs.py` と CI（`Check docs`） | frontmatter、バッジの値、ダッシュ、太字の崩れ、ビルド |
| 意味のレビュー | レビュー用サブエージェント | 論旨、不確実性、追加された内容、意味の取り違え |
| 基準 | 人間（`criteria.md`） | 何をブロッカーとするか、運用モード |

## ワークフロー

### Step 1: 機械チェックを実行する

```bash
python3 .claude/skills/mdpub-review/scripts/check_docs.py
```

error があれば、レビューに進まずに直して push し直す。
warning（中黒など）は、固有名詞の内部かどうかを書き手が確認する。

### Step 2: レビュー用サブエージェントを起動する

Agent ツールで新しいサブエージェントを起動する（`fork` は使わない。fork は書き手のコンテキストを引き継ぐため）。
プロンプトは下のテンプレートを使い、`{...}` の部分だけを埋める。

渡すもの：

- **元原稿**：ユーザーから受け取った原稿のパス。ユーザーが直接編集したファイルで元原稿がない場合は、「base ブランチ上の版」と書き、`git show origin/main:<path>` で読むよう指示する。新規ファイルでどちらもない場合は「なし」と書く
- **成果物**：PR で追加、変更したドキュメントのパス
- **基準**：`criteria.md` のパス

渡さないもの：

- 推敲の意図、直した理由、判断の経緯
- PR の説明文（推敲で直した点が書いてあるため）
- 書き手の要約による基準の言い換え

テンプレート：

```
あなたは mdpub（日本語の技術メモサイト）のドキュメント PR のレビュアーです。
次のファイルを自分で読んでレビューしてください。

- 基準: .claude/skills/mdpub-review/criteria.md
- 文章規範: .claude/skills/japanese-tech-writing/SKILL.md
- 元原稿: {元原稿のパス / base ブランチ上の版（git show origin/main:<path>）/ なし}
- 成果物: {成果物のパス（複数可）}

PR の説明文やコミットメッセージは読まないでください。
元原稿と成果物を比べ、criteria.md の「ブロッカー」「軽微」に当たるものを挙げてください。
元原稿が「なし」の場合は、成果物単体で判断できる項目（意味の取り違え、公開してはいけない情報、軽微）だけを見てください。
ファイルの編集はしないでください。

出力は次の形式だけにしてください。指摘がなければ「指摘なし」とだけ書いてください。

- [ブロッカー|軽微] <ファイル>:<行>
  - 該当箇所: 「<成果物の該当文>」
  - 元原稿: 「<元原稿の対応する文>」（ない場合は「なし」）
  - 理由: <criteria.md のどの項目に当たるか、一文で>
```

### Step 3: 指摘を処理する

- **ブロッカーがある場合**：マージしない。指摘が正しければ直して push し、Step 1 からやり直す。指摘が誤りだと考える場合も、書き手が自分でブロッカーを取り消すことはしない。理由を添えてユーザーに判断を仰ぐ
- **軽微だけの場合**：直す価値があるものは、同じ PR で直してよい。直さないものは Step 4 のコメントに残す

レビューをやり直すときは、新しいサブエージェントを起動する。前回のレビュアーに書き手の反論を伝えて考え直させることはしない。

### Step 4: 結果を PR にコメントする

レビュアーの出力を、手を加えずに PR にコメントする。
最後に、機械チェックの結果と、Step 3 で直したもの、直さなかったものを書き手として一行ずつ添える。

### Step 5: マージする、または報告して止める

`criteria.md` の `mode` を読む。

- **report-only**：マージせず、ユーザーに結果を報告する
- **auto-merge**：`criteria.md` の「マージの条件」をすべて満たすことを確認してからマージする。満たさない条件があれば、どれが満たされていないかをユーザーに報告して止める

マージ後は、main への push をきっかけに GitHub Actions がデプロイする。

## 注意事項

- `criteria.md` は人間が確定させる基準の原本である。エージェントは自分の判断で書き換えない
- レビュアーも書き手と同じモデルなので、モデル自体の癖までは独立しない。独立させているのは「書き手の思考過程を知らない」という点だけである
