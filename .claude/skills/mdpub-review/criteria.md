# mdpub レビュー基準

このファイルは、ドキュメントの PR をマージしてよいかを判断する基準の原本（SSOT）である。
書き手（推敲したエージェント）とレビュアー（レビュー用サブエージェント）は、それぞれがこのファイルを直接読む。
書き手が要約してレビュアーに渡すことはしない。

基準の中身は人間が決める。
エージェントはこのファイルを自分の判断で書き換えない。
変更したい点があれば、PR で提案して人間が確定させる。

## 運用モード

```
mode: report-only
```

- **report-only**：レビュー結果を PR にコメントし、ユーザーに報告するだけで止める。マージは人間が行う
- **auto-merge**：「マージの条件」をすべて満たしたら、エージェントがマージする

人間の判断とレビュアーの判断が数回続けて一致したら、`auto-merge` に切り替える。

## マージの条件

次のすべてを満たすときに限り、マージしてよい。

1. PR の変更が `src/content/docs/` 配下だけである（スキル、ワークフロー、設定の変更は必ず人間がマージする）
2. CI（`Check docs`：機械チェックとビルド）が通っている
3. レビュアーの指摘に「ブロッカー」が 0 件である

「軽微」の指摘は、PR にコメントとして残したうえでマージしてよい。

## ブロッカー

1 件でもあればマージしない。

- **論旨の改変**：原稿の主張、結論、問いの立て方が変わっている。段落の削除や再配置で、論証の順序や重みが変わったものも含む
- **不確実性の改変**：原稿で推量、可能性、疑問として書かれていた文が断定になっている。逆に、原稿で言い切っていた主張が根拠なく弱められている
- **原稿にない内容の追加**：原稿にない事実、数値、日付、固有名、引用、URL が足されている
- **意味の取り違え**：指示語や主語の取り違えで、原稿と違う意味に読める
- **公開してはいけない情報**：個人情報、認証情報、社内の非公開情報らしきものが含まれている

判断に迷う指摘はブロッカーとして扱う。

## 軽微

マージは止めない。

- 語の選び方、言い回し、文のリズム
- `japanese-tech-writing` の規範に照らした、意味を変えない範囲の改善余地
- 見出しや表の体裁

## レビューの対象外

- 原稿の主張そのものの是非。書き手の意見に反論することはレビュアーの役割ではない
- 元記事の内容が正しいかどうか（原稿に書かれた要約を、元記事と照合して事実確認することはしない）
